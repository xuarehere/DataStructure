003/哈希表 · 字符串 · 滑动窗口/中等/n ≤ 10⁵

无重复字符的最长子串给你一个字符串 s，找出其中不含重复字符的最长子串，返回它的长度。

这道题真正难的不是哈希表，而是承认窗口不需要回头。一旦你接受"左把手永不左移"，题目就从"枚举全部子串"塌缩成"一次单向推进"。

O(n)时间 · 每个字符进窗一次
O(min(n,σ))空间 · σ 为字符集大小
6刀切至最小原子
3典型崩溃反例
刀 0

立具象母图与核心二元冲突

root topology & tension

先不碰代码。把题目摊成一张图：一条只朝右的跑道、一只只会伸缩的取景框、一本记着"上次落脚点"的点名册。三者就是全部状态，缺任何一角，后面某个分支就失去解释力。

朴素直觉 · 枚举候选

所有子串共 C(n+1,2) ≈ n²/2 个，逐个切出来判重；每个候选再花 O(长度) 验证是否重复。

代价：O(n³) 最坏面 · n = 10⁵ 直接超时

物理现实 · 窗口推进

合法窗口的右端只有 n 种取值。只要"以 right 结尾的最长合法窗口"能从"以 right−1 结尾的"推出来，候选就不必再生。

代价：每字符进窗 1 次 · O(n)
冲突收敛为一句

不要问"哪个子串最长"，只问"刚踩下的这个字符，逼我把左把手推到哪"。前者是搜索，后者是推演。

地标 ①字符跑道 s

只读，永不改写。右把手在这个跑道上单向步行，从头走到尾，没有第二次机会。

地标 ②取景框 [left, right]

左把手可以向右"跳跃"，右把手只能 +1。框内所有字符互不相同——这是唯一需要维护的东西。

地标 ③点名册 last

记每个字符"上一次落脚"的下标。它回答的不是"在不在窗内"，而是"该跳到哪"。

不变量 I任意时刻，窗口 [left, right] 内所有字符互不相同。整道题的每一刀、每一行代码，都只服务于维持这一句。
刀数为什么是 6 而不是 10
  1. 切分是 while not is_atomic(概念): 二分切开 的过程，刀数由题目固有复杂度决定，不预设。
  2. 本题的最小原子同时满足：1 幅画面只表达 1 个状态变化 / 只解决 1 个二元疑问 / 能直投影到 1~3 行代码。
  3. 第 6 刀切完，"为什么 O(n)" 已是自明的几何事实，再往下切即为注水；收官刀（图码同构）不属于"切"，它是把原子重新装配成机器。
刀 1

空间定界刀

spatial cut
切分 #1

把"整个字符串"切成"窗口内 / 窗口外"

1 画面 · 1 疑问
图 1 · 七格跑道里只有中间三格"活着"；左边已判死刑，右边尚未出生。
唯一疑问

这一步要维护的范围，是整个 s，还是只有一段？

→ 只有 [left, right]。范围一旦定界，"判重"的工作量就从 n² 个候选压成 1 个窗口。

代码投影 
left = 0                        # 左把手
for right, c in enumerate(s):   # 右把手
这一刀不含任何判断，它只决定"谁归我管"。
视觉零跳步 一条跑道两种颜色逻辑单分支 框内 / 框外代码直投影 2 行
刀 2

参考系刀

perspective cut
切分 #2

从"看整条串"切到"只看右脚刚踩下的那一个字符"

2 画面 · 1 疑问
图 2 · 探照灯只照刚落下的那格，光斑之外全暗。
唯一疑问

右把手落地的瞬间，全局哪些信息必须进视野？

→ 只有 c 本身 + 它上次落脚的位置。其余字符既不参与判断，也不改变结论。

代码投影 
c = s[right]              # 落点字符
prev = last.get(c, -1)   # 上次落脚点
参考系一换，候选从 n² 塌成 n：每步只回答"这一个字符怎么办"。
视觉零跳步 光斑落在一格逻辑单分支 只有这一个 c代码直投影 2 行
刀 3

双视角刀

two-perspective cut
切分 #3

同一个字符的两个投影：它"是什么" vs 它"上次在哪"

2 画面 · 1 疑问
图 3 · 同一个 'c' 的两张脸：左边只能回答"在"，右边能回答"在第 2 格"。
唯一疑问

记"这个字符在窗内存在"，还是记"它上一次落脚的位置"？

→ 必须记位置。set 只能让你一格一格挪左把手；last[c] 才能一步跳到 c 之后。

代码投影 
last = {}          # 点名册
last[c] = right    # 覆写落脚点
这是本题的基因突变点：O(2n) 的逐格收缩 → O(n) 的定点跳跃。
视觉零跳步 两表并置逻辑单分支 存在性 / 位置代码直投影 2 行
刀 4

边界探照灯刀

boundary radar cut
切分 #4

三种态：没有 / 在窗外（幽灵）/ 在窗内（真冲突）

2 画面 · 1 疑问
图 4 · 两框重叠：实线是正确窗口，虚线是把手回退后的错误窗口，里面藏着两个 b。
唯一疑问

当 prev 落在窗口外时，左把手到底动、还是不动？

→ 不动。只有 prev ≥ left 才是真冲突；prev < left 是幽灵，必须无视。

代码投影 
if prev >= left:          # 还赖在窗内？
    left = prev + 1        # 越过它
# 等价一行：left = max(left, prev + 1)
这条守卫同时干两件事：判冲突 + 掐死左把手的回退。
视觉零跳步 两框重叠即错因逻辑单分支 prev 与 left 的大小代码直投影 2 行
刀 5

守恒刀

invariant / elimination cut
切分 #5

窗口长度不必"数"，它是两个端点的函数

2 画面 · 1 疑问
图 5 · 尺子量的是两个把手之间的距离，不是数格子数出来的。
唯一疑问

当前窗口有多长，还要不要再遍历数一遍？

→ 不要。长度 = right − left + 1。计数换成做差，顺手消掉"删字符漏删 / 多删"的一整类 bug。

代码投影 
ans = max(ans, right - left + 1)
# 端点一减，长度自现
凡是"数一数"能换成"算一算"的地方，都换成算。
视觉零跳步 一条尺子线逻辑单分支 取大 / 不取代码直投影 1 行

摊还刀

amortized cut
切分 #6

为什么它不会退化成 O(n²)：左把手的里程表只朝右

2 画面 · 1 疑问
图 6 · 把手从左往右的里程是有限的：所有跳跃加起来也走不完一整条跑道。
唯一疑问

左把手会不会在跳跃里走回头路，把总代价顶成 O(n²)？

for right in range(n):     # 只有一层

收官刀 · 左码右图同构

visual-code isomorphism

六个原子装配成一台机器。右侧单步执行时，左侧对应代码行同步高亮；点击左侧任意一行，右侧与之对应的画面元件会闪一下——这就是"这行代码在物理世界上干了什么"。

  3. 3 left = 0 # 左把手
  4. 4 ans = 0 # 历史最长
  5. 5 for right, c in enumerate(s): # 右把手单向推进

阶段解耦沙盒

stage decoupling

把同一台机器拆成三个互不重叠的阶段。任何一次循环只命中 A 与 C，B 是条件分支；三者正交，才谈得上"逐步可调试"。

阶段 A · 扩张

条件：prev == −1 或 prev < left。
动作：左把手不动，右把手已 +1 进窗。
窗内字符集扩大一格。

本步命中 0 次

阶段 B · 跳跃

条件：prev ≥ left（真冲突）。
动作：left = prev + 1，一次指针赋值完成收缩，不逐格删。
窗内可能一次丢掉多个字符。

本步命中 0 次

阶段 C · 记账

条件：每步必执行。
动作：last[c] = right；ans = max(ans, right−left+1)。
状态与最优值在同一个原子内一起落地。

本步命中 0 次

09

解法全集：从候选全集到状态机

all solutions

五种写法不是五个答案，而是同一条思路上的五个演化站位。每一种都保留它的位置——面试里知道"为什么不用 A"，比只会写 C 更有说服力。

解法 A

暴力枚举全部子串 + 集合判重

时间 O(n³) · 空间 O(n)
def lengthOfLongestSubstring(s):
    n, ans = len(s), 0
    for i in range(n):
        for j in range(i, n):
            if len(set(s[i:j+1])) == j - i + 1:
                ans = max(ans, j - i + 1)
    return ans

把"候选全集"穷尽：C(n+1,2) 个窗口，每个切片 + 建集合。n = 10⁵ 必然超时，但它是问题的定义面。

致命点：切片 O(n) + 建集合 O(n)，三层叠成 O(n³)。

解法 B

滑动窗口 + 集合（左把手逐格右移）

时间 O(2n) = O(n) · 空间 O(min(n, σ))
def lengthOfLongestSubstring(s):
    seen, left, ans = set(), 0, 0
    for right, c in enumerate(s):
        while c in seen:        # 撞了，逐格吐
            seen.remove(s[left])
            left += 1
        seen.add(c)
        ans = max(ans, right - left + 1)
    return ans

窗口只维护"在不在"。每个字符最多进集合一次、出集合一次，所以 while 的总轮数 ≤ n，整体 O(2n)。

它答不出"该跳到哪"，所以收缩只能一格一格走；最坏情况（如 "aaaa…" 之外的构造）多一层循环开销。

解法 C · 本页主解

滑动窗口 + 位置字典（跳跃）

时间 O(n) 严格 · 空间 O(min(n, σ))
def lengthOfLongestSubstring(s):
    last, left, ans = {}, 0, 0
    for right, c in enumerate(s):
        prev = last.get(c, -1)
        if prev >= left:        # 还赖在窗内
            left = prev + 1      # 一步越过
        last[c] = right
        ans = max(ans, right - left + 1)
    return ans

把 B 的 while 换成一次赋值：收缩从 O(k) 降到 O(1)。循环体无内层循环，时间严格线性。

唯一风险：守卫 prev >= left 漏写或写成 >，左把手会回退（见"报错复盘"）。

解法 D

DP 滚动：以 i 结尾的最长无重复长度

时间 O(n) · 空间 O(min(n, σ))
def lengthOfLongestSubstring(s):
    last, dp, ans = {}, 0, 0
    for i, c in enumerate(s):
        prev = last.get(c, -1)
        dp = dp + 1 if prev < i - dp else i - prev
        last[c] = i
        ans = max(ans, dp)
    return ans

定义 f(i) = 以 i 结尾的最长无重复子串长度，转移 f(i) = min(f(i−1)+1, i−prev)。与解法 C 完全同构：i − dp 就是 left。

少维护一个 left，常数更小；代价是状态定义要讲清楚，否则面试官会追问"dp 是什么"。

解法 E

常数优化：128 长度数组替代字典

时间 O(n) · 空间 O(128)
last = [-1] * 128                  # ord(c) 直接寻址
# 适合题目给定的"字母 / 数字 / 符号 / 空格"
# 出现非 ASCII 字符必须退回 dict

把哈希查找换成数组寻址，常数再降一档；空间固定 128，不受 n 影响。

前提是字符集已知且封闭。字符集开放时数组方案会索引越界或静默截断。

对比矩阵

comparison matrix

从"能不能过 10⁵"这一栏开始看：三条 O(n) 解法都能过，区别只在常数、可读性与讲清状态的难度。

解法时间空间过 10⁵关键动作面试定位
A 暴力O(n³)O(n)否枚举候选 + 建集合只用于说清"候选全集有多大"
B 窗口+setO(2n)O(σ)是逐格删字符稳，但需解释 while 为何仍是线性
C 窗口+dictO(n)O(σ)是一次指针跳跃首选，必须写熟
D DP 滚动O(n)O(σ)是f(i) = min(f(i−1)+1, i−prev)进阶：能讲清状态定义即加分
E 数组表O(n)O(128)是ord 寻址常数优化细节，答辩级
一句话取舍

C 与 D 同构：C 维护 left，D 维护 dp，二者互为 i − dp = left。面试写 C，被追问"能否少维护变量"再上 D。

避坑清单

trap checklist

七条里，前四条是真正会让代码给出错误答案的，后三条属于工程洁癖；先修前四条。

错left = prev + 1
没有 prev ≥ left 守卫，左把手会回退。
对if prev >= left: left = prev + 1
无守卫时 "abba" 得 3，正确答案 2。
错if prev > left:
prev == left 也是真冲突（s[left] == c），漏判。
对if prev >= left:
"aa" 用 > 得 2，正确答案 1。
错right - left
闭区间少算一格，单字符窗口得 0。
对right - left + 1
"b" 应得 1，不是 0。
错last[c] = right; prev = last.get(c, -1)
先记账后比较，prev 恒等于 right，每步都判"自己撞自己"，窗口长度恒为 0。
对prev = last.get(c, -1); ...; last[c] = right
顺序颠倒会让 ans 恒为 0。
错seen.remove(c)
c 是刚落下的字符，本来就不在集合里，remove 会崩。
对seen.remove(s[left])
要删的是窗口左端那个字符，不是新来的。
错return s[best_l:best_r+1]
题目要长度，不要求返回子串。
对return ans
顺带记：子序列（如 "pwke"）不算子串。
错if not s: return 1
空串答案是 0，不是 1。
对ans = 0
循环体一次不进，自然返回 0。

报错复盘

postmortem

按"看到什么 → 为什么 → 改哪一行"的顺序排查，不要凭感觉调参。

WA · 输出 2，期望 1

用例 "aa"：守卫写成了 >

症状
单字符重复的用例答案翻倍。
根因
prev == left 时 s[left] 就是 c，窗口内已存在两个 c，必须跳过。
修法
> 改 >=；或直接写 left = max(left, prev + 1)。
WA · 输出 3，期望 2

用例 "abba"：左把手回退了

症状
窗口变宽，但内部含重复，答案偏大。
根因
prev = 0 已在窗外（幽灵），仍执行 left = prev + 1 把把手拉回 1。
修法
加守卫 prev >= left；把"跳跃"限定为"只许向右"。
TLE · 只过 987 / 1041

n = 10⁵ 时超时

症状
用例越长越慢，时间随 n 二次增长。
根因
用 s[i:j+1] 切片判重，或把窗口长度每次重新 sum/len。
修法
换解法 C（端点做差），删掉一切 O(长度) 的重复统计。
RE · KeyError

集合版删错字符

症状
部分用例直接抛 KeyError: 'x'。
根因
seen.remove(c) 删的是新字符，而它此刻并不在集合里。
修法
删 s[left]，且删完立刻 left += 1，顺序不可倒。

同构基因：改一刀就能迁移

isomorphic genes

这一族题共用"右把手推进 + 左把手只进不退"的骨架，换的是不变量与记账方式。下表每行只写"动了哪一刀"。

76 · 最小覆盖子串

159 / 340 · 至多 K 种字符
把"0 个重复"放宽成"窗口内种类数 ≤ K"；守卫从 prev ≥ left 变成 种类数 > K。
424 · 替换后最长重复子串
不变量换成"长度 − 窗口内最多频次 ≤ k"；点名册升级成频次表。
1004 · 最大连续 1 的个数 III
424 的退化版：把"最多频次"固定成"窗口内 0 的个数"，只需一个计数器。
209 · 长度最小的子数组
目标反转：窗口求"最短满足和 ≥ target"，左把手在满足后继续收缩——同一骨架，反向收敛。
