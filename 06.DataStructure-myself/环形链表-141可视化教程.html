PROOF / 证明链 · 为什么这套动作成立

这个"为什么"，其实是四个独立命题

你卡住的不是"会不会相遇"，而是"凭什么"。拆开看它是四件事，各有各的证明工具；少证任何一条，这个解法就降级成"多数情况能行"。四条都成立，它才叫解法。

#要证的命题用什么证结论强度
P1O(1) 空间下存在判定方法直接构造：两个游标 + 速度差构造性存在
P2有环 ⇒ 必然相遇δ 的模 L 递推 δ ← (δ − 1) mod L确定性，不是概率
P3无环 ⇒ 必然退出fast 的越界 + 循环条件兜底确定性
P4差 1 为什么不可替换gcd(k−1, L) 整除性充要条件，不是经验

P2 的全部内容：把"绝对位置"换成"相对位置"

在直道上谈位置没有意义——两人都在直道时，距离每轮拉大 1 格，不是常数。所以第一步不是"跑"，而是换坐标系：只保留"两人都在环上"的阶段，用环序号 0…L−1 表示位置，并定义

δ = (s − f) mod L  = fast 沿运动方向还要走几格才到 slow

每轮做两件事：s ← s + 1、f ← f + 2。代进 δ 的定义，得到一个不再依赖具体节点的递推：

δt+1 = (δt − 1) mod L  ⟹   δt = (δ0 − t) mod L

取 t = δ0，右边必为 0；而 δ0 最大是 L−1，所以至多 L−1 轮必定归零。"必然相遇"的完整证明就是这两行——零点由算术给出，不由概率给出，也不由"跑得久总会碰上"给出。

这条证明最容易被忽略的推论

δ 从头到尾没有被计算过，也没有被存储过：代码里没有 δ 这个变量，它只是"步长差 = 1"的数学推论。
O(1) 空间不是省出来的，而是"判据换了"白送的——被推断出来的量，不需要被记住。

还得先证一件事：两人"同时在环上"凭什么一定发生

上面的推导全部建立在"δ 有定义"上。如果 fast 一直不进入环、或进去又出来，δ 就是空谈。补这一步：

  • 有环时环挂在直道末端，fast 每轮 2 格，一定先撞进环（比 slow 早 a/2 轮上下）。
  • 进去之后出不来：环里每个节点的唯一出边都指向环内节点，不存在通向 null 的边。
  • slow 每轮 1 格，走 a 轮后也进入环。
  • 于是存在时刻 t₀ = a，从此恒在环上，δ 有定义，且之后每轮严格 −1。

顺带消除一个常见疑虑：fast 在 slow 还没进环时可能已经在环里绕了 m 圈。这不影响证明——δ 只在"两人都在环上"之后才开始计数，之前绕的圈数被 mod L 全部吸收，取模这个动作本身就在替你擦掉历史。

P4：为什么是 1 对 2，不是 1 对 3

设 fast 每轮走 k 格，同样推导得到

δt = (δ0 − (k−1)·t) mod L

这串数永远落在同一个集合里：δ0 + m(k−1) mod L，即模 L 下由 (k−1) 生成的子群，大小是 L / gcd(k−1, L)。于是：

δ 能取到 0  ⟺  gcd(k−1, L) | δ0
k−1Lgcd结果
1任意1对任意 δ₀ 都整除 ⇒ 必然归零
242δ₀ 为奇数时永不归零（1,3,1,3… 打转）
251恰好能归零——但这是 L 的巧合，不构成保证
363δ₀ ∈ {1,2,4,5} 时永不归零

"快的会从慢的头上跳过去"的严格版本就在这里：不是速度太快，而是步长差与环长不互质，导致 δ 被困在一个够不到 0 的子群里。k−1 = 1 与任何 L 都互质，是唯一"对任意环长都保证"的差——所以 1 对 2 不是习惯，是最小充分保证。

P3：无环为什么必然停

无环时链长 n，fast 每轮 2 格，最多 ⌈n/2⌉ 轮后 fast 变成 null；循环条件 while fast and fast.next 在访问 fast.next.next 之前就把它拦住。若只写 while fast，n 为偶数时会在最后一个节点上访问 None.next——这是 P3 的代码落点，不是题解的书写习惯。

五条常见误解，逐条对账

直觉说法实际成立的说法
"快的会从慢的头上跳过去"差 1 时每轮只追近 1 格，位置是整数，不存在跨越；会跳过的是"差 ≥2 且与 L 不互质"的情形
"两人必须同时进环才成立"不必。只需存在时刻之后两人都在环上，δ 才有意义；进环时刻本来就不用相同
"要记下 δ 才能判断"δ 不存。它由步长差 1 隐含保证，代码里只有两个指针变量
"重合是 slow 追上了 fast"方向固定：fast 从背后追上 slow。所以循环里先移动再判等，不会漏掉第一次重合
"fast 走 3 步更快"看 P4：k−1=2 时 gcd(2,L) 决定成败，L=4、δ₀ 奇数就永远追不上

这张证明真正值钱的东西：判据降维

四段证明拼起来，可迁移的只有一句方法论：

依赖历史的判据（你来过没有）  →  依赖当前状态的不变量（你俩此刻重合没有）

历史需要存储，状态只需要观察。这就是为什么 O(1) 在这里不是妥协，而是换了个判据之后的自然结果。同族题全部是这一条的变体：142 找入口（相遇后 a = L − b）、876 找中点（δ 退化成常数 L/2 的极端情形）、143 把两个模型串起来。

01 / 模型 · L1 放大「三个色块」

三个区间，两格节点

链表被切成直道与环之后，全局状态只需要三个数：还剩多长直道、环多长、待追多远。这三个数就是你在纸上的全部画面。

区间定义长度动态行为
Sₐ 直道区间：head 到环入口之前的节点 a slow 每走一步就吃掉一格，只减不增；slow 入环即耗尽（a=0）
S_c 环区间：入口节点开始的闭合回路 L 恒定闭合，没有出口。fast 一旦进来就永远在里面转
S_δ 待追弧：沿运动方向，从 fast 到 slow 的那段弧 δ 每轮恰好 -1，归零即相遇。这是整个算法唯一的收敛量
δ = ( pos(slow) − pos(fast) ) mod L   ·   每轮 δ ← δ − 1   ·   相遇 ⟺ δ = 0

把 δ 想成 206 里的 Sᵤ：一个不断缩小的区间，只是它长在环上、并绕着圈走。你在 206 里已经接受"待处理区间一路缩小到零"这个画面，这里只是把它搬到环上——这是本次唯一的认知迁移成本。

节点是双格结构（这是你上次专门要求过的画法）

每个节点两个格子：数据域（存 val）与指针域（存"指向谁"）。指针域里写的不是箭头装饰，而是后继节点的值；尾节点指向环入口时，指针域会写成入口节点的值，而不是 ∅。这样你随时能核对"链接关系是否还完整"。

I1 · 无环侧
fast 每步 +2，位移严格大于 slow，因此必然先抵达链表末尾之外。循环因 fast 越界而终止，这本身就证明了"无环"，不需要额外判据。
I2 · 有环侧
两游标都进环后沿同一方向运动。以 slow 为参照系，fast 每轮净前进 +1，所以待追弧 δ 单调减 1，必在 ≤ L 步内归零。
公理 · 位移账本
每轮：Δslow = +1，Δfast = +2，Δδ = +1 − 2 = −1（mod L）。这个恒等式是"为什么一定相遇"的全部数学，与环多大、从哪进无关。

推论：由于 δ 的初值最大为 L−1，收敛所需轮数 ≤ L；而 slow 走到尾最多 n 步，因此总轮数 ≤ n，总时间 O(n)。

02 / 落地 · L2 放大「两条指令 → 相对位移」

把四行代码打包成一个原子算子 F

INTJ 容易在"宏观画面懂了、代码对不上"这里断层。解法是把一轮循环打包成一个不可拆的整体动作 F，再单独检查每行的读写对象。

F = 判界 → slow+1 → fast+2 → 判等   （四个动作串行，顺序固定，不可交换）

为什么顺序不能换

  • 判界必须最先：后面要读 fast.next.next，若 fast 或其 next 为空，这行直接抛出空指针异常。判界就是给后面两行开路。
  • 判等必须最后：初始时 slow 与 fast 站在同一个节点，这是结构性事实而非环的证据。先判等会把"两人同起点"误判为"相遇"。
  • 两个移动不能并行写：slow, fast = slow.next, fast.next.next 在 Python 里靠元组求值可以，但一旦 slow 先动、再用 slow 去算 fast，就会少走一格。

逐行落地表（把代码挂到画面上）

行代码读 / 写对象画面变化改的是什么
1slow = fast = head写两个游标两个标签同时贴到首节点游标初始化
2while fast and fast.next:只读 fast、fast.next不动；等价于问"前面还有格子吗"判据（不改变状态）
3slow = slow.next写 slowSₐ 缩一格；若跨进环，Sₐ 归零游标 + 区间边界
4fast = fast.next.next写 fastδ 缩短 2 的位移；以 slow 为参照净缩 1游标 + δ
5if slow is fast比较两个地址δ = 0 时两标签叠在同一格判据（产出答案）
6return False无fast 停在链表外，环框不存在退出路径

这张表的用法：以后任何链表题，先按"读/写对象 / 画面变化 / 改的是游标还是判据"三列拆一遍，断层会立刻暴露在哪一行。

04 / 纠偏 · L4 补齐认知断层

你的断层具体断在哪一层

断层不在"看不懂代码"，而在"两套描述自由的维度不一致"。先定位，再修。

DIAGNOSIS

你的宏观画面用一个自由度描述状态（区间还剩多少）；代码用两个自由度描述状态（slow 在哪、fast 在哪）。两套描述之间缺一个换算量，所以你只能"看到"区间在缩，却不知道区间长度对应哪一行代码。

这个换算量就是 δ。一旦把"两个绝对位置"折叠成"一个相对距离"，画面与代码就同维了：δ 的每一次 −1，恰好就是一轮循环。这也是 206 里 Sᵣ/Sᵤ 能对上代码的原因——那里的区间长度直接等于 cur 的位置。

五条常见幻觉，逐条掐掉

你可能会想δ 每次可能跳好几格，甚至一步跳过 slow
事实相对位移每轮恰好 +1，δ 只能减 1。只有"步长差 ≥ 2"才可能跳过，而一旦跳过就可能永远错过（见 05 的 gcd 条件）。
你可能会想fast 更快，所以相遇会很快发生
事实收敛速度只取决于相对速度 1。演示 B 里 fast 每轮跑两格，仍要 7 轮才归零。
你可能会想相遇的那个节点就是环的入口
事实a ≠ 0 时相遇点一般不在入口（演示 A 相遇在节点 7，入口是节点 4）。求入口是 142 的额外一步推导。
你可能会想一进循环就可以先判 slow == fast
事实两者初始同点是结构性事实。先判等会让 [1], pos=-1 直接返回 True。
你可能会想环上的"距离"就是画出来的弧长
事实距离是步数模 L，与视觉弧长无关；节点排得疏密不同，δ 也不变。
05 / 解法 · L5 横向：还有哪些走法

四种解法：先要基准，再要最优

基准解不是废物，它是你验证最优解逻辑的对照组。上来只写最优，一旦出错你没有第二把尺子。

解法 0 · 哈希集合（基准，先拿到 AC）

def hasCycle(head):
    seen = set()            # 记录"来过"的节点身份
    while head:
        if head in seen:   # 命中即证明轨迹重复
            return True
        seen.add(head)
        head = head.next
    return False            # 走到空 = 无环

时间 O(n)，空间 O(n)。它把"判重"这个语义讲清楚了，但没有回答"能不能不记住任何东西"——这正是优化动机。

解法 1 · 快慢指针（Floyd，面试标准解）

def hasCycle(head):
    slow = fast = head            # ① 同起点（此时同点不算相遇）
    while fast and fast.next:      # ② 判界：无环则在此退出
        slow = slow.next          # ③ +1 格
        fast = fast.next.next     # ④ +2 格
        if slow is fast:          # ⑤ 地址比较，不是值比较
            return True
    return False                # ⑥ 循环自然退出 = 无环

解法 2 · 改指针 / 改值做标记（知道即可，不作主答案）

思路是走过就把节点标记成"已访问"（改 next 指向自己，或把 val 改成哨兵值），再次命中即判环。空间确实 O(1)，但它修改了输入：评测端如果复用链表，或者你后面还要做 142，数据已经被破坏。面试里写这个会被追问"输入被你改了怎么办"，性价比为负。

解法 3 · 计数上限（走 n+1 步）

无环链表最多 n 个节点，所以走 n 步还没到空就必然有环。逻辑成立，但要先求 n（多一趟遍历），且严重依赖"环长不超过 n"这个隐含约束。它是可用的，只是不如 Floyd 干净。

决策矩阵

解法时间空间改数据面试评价关键约束
快慢指针 FloydO(n)O(1)否首选边界条件必须写对，否则空指针或误判
哈希集合O(n)O(n)否基准 / 保底空间不满足进阶要求
改标记O(n)O(1)是不建议破坏输入，后续题无法复用
计数上限O(n)O(1)否可接受需额外一趟求 n，靠隐含假设

为什么慢指针必须 +1、快指针必须 +2

设相对速度 k（fast 比 slow 每步多走 k−1 格），进入环时待追弧为 δ，环长 L。每一轮 δ ← (δ − (k−1)) mod L。这个同余方程有解的条件是：

gcd(k − 1, L)  整除  δ
相对速度是否能保证相遇原因
1（fast 走 2 步）一定能gcd = 1，整除任何 δ。这是唯一无条件收敛的选择
2（fast 走 3 步）可能永不若 L 为偶数而 δ 为奇数，δ 永远取不到 0，fast 会一次次跳过 slow
0（同速）永不δ 恒定，两人并排转圈，永远不重合

所以"走 2 步"不是习惯，是收敛性约束。这条论证把它从模板记忆升级为模型约束——面试官问"为什么不能走 3 步"时，答 gcd 条件即可，不要答"会跳过"这种没依据的话。

07 / 故障域

避坑清单与报错复盘

这部分是可以跨题复用的资产：下次遇到任何双指针题，先过一遍清单。

避坑清单（七条，按发生频率排序）

  • 循环条件顺序写反：必须是 while fast and fast.next，不能是 fast.next and fast。前者靠短路求值做安全阀，后者在 fast 为空时直接崩。
  • 先判等、后移动：初始同点会被误判为相遇。[1], pos=-1 会错报 True。
  • 漏掉 fast.next 的判空：只写 while fast，fast 走两步时越界。
  • 用值比较代替地址比较：节点值可重复，[1,1,1] 成环会误判。必须 is / ==（引用比较）。
  • 把 pos 当参数：函数签名里没有它，它只是评测端建环的施工说明。
  • 在 head 上提前解引用：head.next 在空链表时会抛异常，判断要用 fast 而不是 head。
  • 只移动一个指针：每轮两个指针都必须动，否则 δ 不变化，直接死循环。

09 / 迁移 · 变体与自检

变体训练：自己改题，确认模型边界

同族题只改一两处，就能验证你真的掌握了模型，而不是记住了这道题的答案。

变体 1 · 142 环形链表 II（求入口）

设直道长 a，入口到相遇点长 b，环长 L。相遇时 slow 走了 a + b，fast 走了 a + b + L，且 fast 是 slow 的两倍：

2(a + b) = a + b + L   ⟹   a = L − b

含义：从 head 走到入口的距离 a，恰好等于从相遇点继续走到入口的距离 L − b。所以相遇后让 slow 回到 head，两个指针都改成每次 1 格同速前进，再次相遇的位置就是入口。

# 在 141 的相遇判定之后追加三行
slow = head
while slow is not fast:
    slow = slow.next
    fast = fast.next
return slow          # 环入口

变体 2 · 求环长

相遇后固定一个指针不动，另一个绕行一圈并计数，回到起点时的计数就是 L。这是"相遇点是一个可靠的锚"这一性质的直接用途。

变体 3 · 876 链表的中间节点 / 143 重排链表

876 只用到骨架里的一半：不需要判等，fast 到尽头时 slow 就是中点。143 是三模型串行：876 找中点 → 206 反转后半段 → 归并两段。能做 143 而边界不崩，就说明 M-L1 真的收敛成了模板。
